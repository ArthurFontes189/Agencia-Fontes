# Fluxo de trabalho

## Resumo
Escolher o negócio, montar a demo, mostrar pessoalmente, e só se o cliente aceitar
seguir para o site final. Cada cliente tem repositório próprio, criado a partir do
template `templates/site-base`.

## Fases
| Fase | O que acontece | Onde roda | Quem decide avançar |
|---|---|---|---|
| 1. Demo | Cópia do template com a cara do negócio, 1 a 2 dias | Local (nunca público com a marca) | Primo apresenta |
| 2. Site final | Conteúdo real, contrato, domínio, publicação | GitHub Pages | Cliente aprova |
| 3. Upgrades | Google Meu Negócio, conteúdo, anúncios | Fora do código | Cliente contrata |
| 4. Sistema | Agenda, clientes, painel | Projeto separado com banco | Cliente contrata |

## Escolha do alvo (antes da demo)
Priorize negócio com dor visível: sem site, site antigo, só Instagram, agenda bagunçada
no WhatsApp. Um nicho e um bairro por vez. Não monte demo para quem ainda não foi
visto pessoalmente por quem vai vender.

## Regras de ouro
- Demo só aparece para o dono, presencialmente ou em link privado.
- Nada inventado: dado desconhecido é confirmado com o dono.
- Vende-se só o que está no catálogo de planos. Pedido fora dele passa pelos sócios.
- Melhorias no template não chegam sozinhas aos clientes já criados: cada cliente é uma
  cópia. Corrija o que for crítico à mão, projeto a projeto.

## Registro
Cada cliente tem `STATUS.md` (fase, combinado, pendências). Atualize ao fim de cada dia
de trabalho nele.
